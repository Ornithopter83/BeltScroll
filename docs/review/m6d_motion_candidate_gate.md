# M6D 공격 후보 모션 검수

## 확보 및 추출

`assets/art/player/elven_fighter_dark_fantasy_attack1_sheet_v1_candidate_1254x1254.png`에서 신규 1254×1254 공격 시트를 확인했다. 파일명은 RESOURCE가 아닌 candidate attack sheet로 되어 있지만 그림은 2×2 배열이다. 시트를 절반씩 분리해 627×627 RGBA 프레임 4개를 메모리에서 독립 추출하고 원본 순서대로 재생했다: 좌상, 우상, 좌하, 우하. 개별 추출 PNG나 아트 원본을 만들거나 수정하지 않았다.

네 칸은 같은 다크 판타지 엘프 전사로 시각적으로 보이며 헤어, 얼굴, 갑옷, 복장 팔레트가 이어진다. 이는 시각적 관찰이며 인물 동일성의 승인 판정은 아니다. 포즈는 좌상 가드/대기, 우상 낮춘 준비, 좌하 펀치, 우하 가드로 보인다. 셀 사이의 실제 애니메이션 순서 의도는 별도 원화 지시가 없어 미확정이다.

## 검수 측정

Godot 4.7.2, OpenGL Compatibility, 표시 창 1920×1080에서 각 독립 프레임을 120ms 목표로 격리 재생했다. `observed_ms`는 프레임 전환 후 `frame_post_draw`마다 잰 실제 wall-clock 노출이다. RGBA 픽셀 변경량은 직전 셀의 crop과 비교했다. alpha bounds는 각 627×627 crop 내 α≥0.05 픽셀의 경계다. alpha pixels 괄호는 0<α<0.999인 부분 alpha 픽셀 수다. `edge alpha T/B/L/R`는 crop의 위/아래/좌/우 테두리에 있는 α≥0.05 픽셀 수다. 하단 중심은 crop 내 가장 낮은 alpha 행의 좌우 끝 중점으로, 실제 지지발 자동 판정이 아니다.

| 셀 순서 | alpha bounds (x,y,w,h) | alpha pixels (partial) | 하단 중심 추정 (x,y) | edge alpha T/B/L/R | 실측 노출 | 렌더 프레임 | 직전 crop 대비 변경 픽셀 |
|---|---|---:|---:|---:|---:|---:|---:|
| 좌상 | 89,9 · 489×618 | 131,467 (131,135) | 323,626 | 0 / 49 / 0 / 0 | 124.9 ms | 4 | 기준 프레임 |
| 우상 | 53,33 · 548×594 | 141,209 (140,819) | 78,626 | 0 / 49 / 0 / 0 | 123.8 ms | 4 | 170,660 |
| 좌하 | 60,0 · 567×598 | 150,824 (150,210) | 86,597 | 35 / 0 / 0 / 50 | 126.5 ms | 4 | 197,918 |
| 우하 | 0,0 · 602×600 | 132,417 (132,014) | 102,599 | 47 / 0 / 49 / 0 | 123.6 ms | 4 | 179,113 |

네 프레임 모두 서로 다른 원본 픽셀을 포함하며, 측정 범위에서 프레임 간 변경 픽셀은 170,660~197,918이다. 재생 중 보간, 좌우 반전, 회전, 스쿼시/스트레치 등 절차적(procedural) 포즈 변경은 없었다. 이 수치는 시트에 서로 다른 그림이 있음을 확인하지만, 본편에서의 동작 연속성이나 승인 여부를 정하지는 않는다.

모든 crop의 테두리에 alpha가 남아 있다. 특히 아래 두 셀은 하단 테두리에 49px, 좌하 셀은 상단/우측에 35/50px, 우하 셀은 상단/좌측에 47/49px가 닿는다. 따라서 현재 2×2 균등 분할은 프레임마다 일부 그림을 경계에서 자르거나 이웃 셀과 섞을 가능성이 있다. 원본 시트는 알파 투명 배경이지만, 분할선에 여백이 있는 깨끗한 스프라이트 시트라고 검증되지는 않았다. 하단 중심과 발 anchor 판정은 이 경계 접촉 때문에 잠정값이며 사람의 발 지지/동일성 검토가 남는다.

## 판정과 파일

- 비교 보드: [m6d_motion_candidate_comparison.png](../../assets/art/review/m6d_motion_candidate_comparison.png)
- 재실행: 프로젝트 루트에서 `godot.exe --path . --script tools/build_m6d_motion_candidate_review.gd`
- 시트 검출은 `assets/art/player` 내 RESOURCE 이름 PNG를 우선하고, 없으면 attack + sheet 이름의 PNG를 찾는다. 이 실행에서는 candidate attack sheet fallback을 사용했다. 시트가 2×2로 짝수 크기인지 확인하고 좌상→우상→좌하→우하로 잘라 재생한다.
- 네 원화는 계속 미승인 상태다. 검수 도구와 이미지 외에 PlayerArt, 본편 런타임, manifest, allowlist는 변경하지 않았다.
- 판정: 시트 독립 crop/실측 재생 **확인**, 프레임별 alpha **측정**, 크롭 테두리 alpha **관찰됨**, 인물 동일성 및 지지발 **사람 검토 필요**, 후보 승인 **미수행**, 런타임 등록 **없음**.

2026-10-10 HIGH 재검수에서도 같은 후보 시트를 비헤드리스가 아닌 Godot 4.7.2 Window에서 재생했다. 최신 `observed_ms`는 124.9, 123.8, 126.5, 123.6ms이고 셀별 렌더 수는 4, 변경 픽셀 수는 170,660~197,918이다. 전체 로그는 `.qa_logs/m6d_motion_candidate_high_recheck.log`에 남겼다. 비교 PNG는 타이밍 재생 전 보드 캡처이므로 그 한 장 자체를 영상 증거로 읽지 않는다. 프레임 전환과 실측 시간은 로그로 확인했으며, 셀 경계 alpha·순서 의도·동일성·실제 지지발은 계속 사람 검토 대상이다.

실행 중 Godot이 시스템 인증서 저장소 관련 환경 오류를 출력했지만, 창 캡처 PNG 저장/read-back과 네 프레임 재생 로그는 완료됐다. 환경 오류를 우회하는 프로젝트 코드는 추가하지 않았다.
