# 수동 물리 입력 인수 검수 게이트

## 목적과 제한

이 절차는 Godot 본편 메인 씬을 1920×1080 창으로 실행하고 검사자가 실제 키보드·마우스 조작과 화면 반응을 직접 확인해 결과를 기록하는 수동 인수 경로입니다. 입력 로그는 Godot이 전달한 이벤트, 상태 전이, 시각, 창 포커스 정보를 남깁니다. 로그만으로 물리 장치 출처를 증명하지 않습니다. Godot 입력 이벤트에는 실제 장치 입력과 모든 방식의 합성 입력을 확실히 구별하는 출처 증명 정보가 없으므로 장치 조작 여부는 검사자의 직접 관찰로 기록합니다. 반복 키(echo), 취소 마우스 이벤트, 비기본 장치 식별자처럼 의심 표식이 있는 이벤트는 별도 표시하되 이것만으로 합성 여부를 단정하지 않습니다.

무인 또는 리디렉션된 콘솔에서는 검사자 관찰이 불가능합니다. 이 경우 결과는 `BLOCKED_UNVERIFIED`이며 승인이나 인수 완료로 해석하지 않습니다.

## 실행

Windows PowerShell 5.1에서 저장소 루트 기준으로 실행합니다. PowerShell 텍스트 출력은 UTF-8로 설정하며, 로그 JSONL과 수동 결과 JSON은 시스템 임시 디렉터리에 생성합니다.

```powershell
.\tools\run_manual_input_acceptance.ps1 -GodotPath 'C:\Path\To\Godot_v4.exe'
```

Godot이 `PATH`에 있으면 `-GodotPath`를 생략할 수 있습니다. 다른 로그 위치를 원하면 `-OutputDirectory`를 지정합니다. 실행기는 기존 `application/run/main_scene`을 불러오고 1920×1080 창 크기를 요청합니다. 입력을 주입하거나 게임 데이터, 전투 상태, 승인 기록을 변경하지 않습니다.

## 검사 절차

1. 본편 창이 열리고 포커스를 가진 것을 확인합니다. 로그의 `session_start`와 `window_focus` 기록을 확인합니다.
2. 각 항목을 실제 키보드 또는 마우스로 눌렀다 놓습니다. 화면의 반응과 기대한 기능을 확인하고, 이벤트 로그에서 눌림/해제 전이와 시각을 확인합니다.
3. 창 포커스를 다른 창으로 옮긴 뒤 돌아옵니다. `window_focus`의 `focus_lost`와 `focused` 기록이 일반 입력과 별도 레코드인지 확인합니다.
4. 게임 창을 닫습니다. 실행기가 항목별 화면 반응, 실제 장치의 직접 관찰, 포커스 동작, 메모를 물으면 검사자가 결과를 직접 입력합니다.
5. `manual-review.json`의 수동 결과를 이벤트 로그와 함께 검토합니다. 모든 항목이 pass이고 검사자가 직접 확인했을 때에만 `MANUAL_REVIEW_RECORDED`가 됩니다. 미실시, 실패, 포커스 확인 누락, 물리 장치 확인 누락은 미검증 상태로 남습니다.

## 검사 기록표

실행기는 같은 항목을 종료 후 대화형으로 기록합니다. 이 표는 기대 동작과 관찰 대상을 정리하기 위한 것입니다. 키 입력 이벤트와 상태 전이는 기록할 수 있지만 각 기능의 화면 결과는 검사자가 직접 판정합니다.

| 입력 | 이벤트에서 확인할 내용 | 검사자가 직접 확인할 내용 |
|---|---|---|
| Num1–Num9 | 키 눌림/해제, 반복 표식, 타임스탬프 | 각 숫자 키의 본편 화면 반응 |
| W, A, S, D | 키 눌림/해제와 상태 전이 | 이동/방향 반응 |
| Space | 눌림/해제와 상태 전이 | 점프 등 본편 반응 |
| Shift | 눌림/해제와 상태 전이 | 본편에서 연결된 반응 |
| J | 눌림/해제와 연결 action | 공격 등 본편 반응 |
| 마우스 좌클릭 | 버튼 눌림/해제, 위치, 취소 표식 | 클릭에 연결된 본편 반응 |
| Esc | 눌림/해제와 연결 action | 취소/일시정지 등 본편 반응 |
| 창 포커스 | 별도 `window_focus` 레코드 | 포커스 상실 후 복귀 시 입력/화면 상태 |

## 판정 및 산출물

출력 디렉터리의 `input-events.jsonl`은 시간 순 이벤트 기록이며 `manual-review.json`은 검사자가 입력한 검수 결과입니다. 이벤트에는 UTC 시각과 프로세스 기준 단조 시각(마이크로초), 장치 식별자, 전이, 연결 action, 포커스 상태, 합성 의심 표식이 포함됩니다. 장치 식별자는 물리 장치 증명이 아닙니다. 실제 키보드·마우스 관찰이나 화면 반응이 확인되지 않은 항목은 pass로 기재하지 않습니다. 무인 실행은 `BLOCKED_UNVERIFIED`와 종료 코드 2로 끝나며 검수 승인 상태를 만들지 않습니다.
