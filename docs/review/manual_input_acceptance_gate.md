# 최종 통합 수동 인수 게이트

## 목적과 판정

이 절차는 실제 사람이 완성 빌드/프로젝트를 실행하고 키보드·마우스 동작, 화면 표시, 전투 HUD, 독립 편집기 왕복, 원화 움직임을 직접 확인해 기록하는 최종 인수 절차다. Godot 이벤트 로그는 입력 시각·상태 전이·창 포커스를 남기지만 장치 출처를 증명하지 않는다. 반복 키, 취소 마우스 입력, 비기본 장치 식별자 같은 표식은 의심 자료일 뿐 합성 입력 판정이 아니다.

무인 또는 표준 입력 리디렉션 실행은 게임을 띄우지 않고 `BLOCKED_UNVERIFIED`와 종료 코드 `2`를 기록한다. 자동 입력, GUI self-test, 로그 존재, 자동 캡처는 사람의 직접 관찰을 대체하지 않는다. 모든 필수 입력과 표시/편집기/원화 항목, 프로세스 종료 코드, 포커스 복귀, 실제 장치 확인이 충족되어야 `MANUAL_REVIEW_RECORDED`가 된다. 이는 기록 완료 상태이며 제품의 무조건적 출시 승인이나 원화 승인과 동의어가 아니다.

## 실행 준비

프로젝트 루트의 Windows PowerShell 5.1에서 UTF-8을 설정하고 문서를 읽는다. Godot 실행 파일과 게임 창을 표시할 수 있는 1920×1080 디스플레이를 준비한다. 화면 배율은 게임 원화 기준 3배로 확인할 수 있도록 전체 화면으로 실행한다.

```powershell
$OutputEncoding = [Console]::OutputEncoding = New-Object System.Text.UTF8Encoding($false)
Get-Content -Encoding UTF8 .\docs\review\manual_input_acceptance_gate.md
.\tools\run_manual_input_acceptance.ps1 -GodotPath 'C:\Path\To\Godot_v4.exe'
```

Godot이 PATH에 있으면 `-GodotPath`를 생략한다. 증거 기본 위치는 시스템 임시 폴더 아래 새 `BeltScrollManualInput_*` 디렉터리다. 고정 출력 폴더를 지정해도 기존 `input-events.jsonl` 또는 `manual-review.json`이 발견되면 새 `session_<시각>_<id>` 폴더를 만들므로 기존 기록을 덮어쓰지 않는다.

```powershell
.\tools\run_manual_input_acceptance.ps1 -GodotPath 'C:\Path\To\Godot_v4.exe' -OutputDirectory 'D:\BeltScrollAcceptance'
```

실행기는 프로젝트의 기본 메인 씬을 1920×1080 전체화면으로 연다. 실행 인수는 입력을 주입하지 않는다. 게임 안에서 실제로 키/마우스를 조작하고 체크 질문은 화면을 관찰한 뒤에만 답한다. 일반 사용자가 보는 3배 크기가 맞는지 함께 확인한다. 요구 해상도나 3배 표시가 실제 화면과 다르면 `pass`를 선택하지 않는다.

## 실행 순서

1. **화면과 포커스:** 본편 메인 메뉴/게임이 뜨는지 확인한다. 1920×1080 전체화면, 원화 기준 3배 표시, 화면 잘림/비정상 stretch 여부를 본다. 게임 창에 포커스를 둔 채 시작한다.
2. **숫자 입력:** Num1~9를 하나씩 눌렀다 놓는다. 각 키의 본편 화면 반응을 확인한다. 특히 Num4와 Num5의 슬롯 이름·준비/사용/쿨다운 표시와 실제 동작이 서로 구분되는지 본다. 키패드 숫자를 사용하는 환경이면 그 사실을 메모한다.
3. **이동 입력:** W, A, S, D를 각각 눌렀다 놓고 네 방향의 이동/방향 전환을 확인한다. 이어 두 방향을 바꾸어 전환과 복귀를 본다.
4. **동작과 공격:** Space를 눌러 점프 반응, Shift를 눌러 게임에 연결된 반응, J를 눌러 기본 공격, 마우스 좌클릭을 눌러 연결 동작을 각각 관찰한다. 키를 누른 상태와 놓은 뒤 모두 확인한다.
5. **전투 HUD와 피격:** 전투 중 양측 체력바, 즉 Player 체력 바와 각 Raider 머리 위 체력 바가 보이는지 확인한다. 적에게 접근해 공격을 주고받으며 양측 체력 변화가 맞는지 관찰한다. 스킬 Num4/Num5를 각각 사용해 슬롯/상태/이펙트 차이를 확인한다.
6. **Esc와 포커스:** Esc를 눌러 본편에 연결된 일시정지/메뉴 반응을 본다. 복귀 후 게임 창에서 다른 창으로 포커스를 옮겼다가 돌아와 `window_focus` 상실/복귀 기록과 입력 회복을 확인한다. 검수 후 게임 창은 직접 닫는다(필요하면 실제 키보드로 Alt+F4).
7. **독립 편집기 수동 왕복:** [편집기 인수 게이트](editor_acceptance_gate.md)의 GUI를 직접 열어 새 데이터 항목 생성, 필드 수정, 저장, 닫은 뒤 재열기, 저장값 확인, 게임에 재적용/동기화를 순서대로 한다. 각각의 성공을 직접 확인한다. `--self-test`나 자동 GUI acceptance 결과로 이 항목을 통과 처리하지 않는다.
8. **원화/움직임 시각 검수:** 3배 크기와 실제 게임 크기에서 얼굴·귀·머리·의상 identity가 유지되는지 본다. 달리기 루프에서 좌우 발의 선후 관계와 보폭이 번갈아 바뀌는지 확인한다. 방향 전환/스킬2 회전에서 몸통·골반·지지발의 회전이 보이는지 본다. 프레임 사이 신체/머리카락/무기 외곽이 순간 이동하거나 튀는 프레임 팝을 확인한다. 후보 원화는 승인 원화로 간주하지 말고 의견과 캡처 경로를 남긴다.
9. **결과 기록:** 게임 창 종료 후 실행기의 모든 개별 질문에 `pass`, `fail`, `not_tested` 중 하나를 기록하고 직접 관찰 여부를 응답한다. 검사자 이름/메모와 캡처 경로를 덧붙인다. 입력 이벤트 및 JSON 결과 경로를 보존한다.

## 입력별 관찰 항목

| 조작 | 직접 관찰할 것 | 로그에서 보조 확인할 것 |
|---|---|---|
| Num1–Num9 | 각 입력의 실제 본편 반응, Num4/Num5 스킬 슬롯과 발동 차이 | 눌림/해제 전이, 연결 action, 타임스탬프 |
| W/A/S/D | 이동, 방향, 전환과 복귀 | 눌림/해제 및 상태 전이 |
| Space | 점프 시작/상승/하강/착지 | 눌림/해제, 연결 action |
| Shift | 게임에서 지정된 기능 반응 | 눌림/해제, 연결 action |
| J | 기본 공격과 전투 화면 변화 | 눌림/해제, 연결 action |
| 마우스 좌클릭 | 클릭에 연결된 본편 동작 | 버튼 상태, 좌표, 취소 표식 |
| Esc | 본편 일시정지/메뉴 반응 | 눌림/해제, 연결 action |
| 창 포커스 | 포커스 상실 전후 화면 상태와 복귀 후 조작 회복 | 별도 `window_focus` 레코드의 `focus_lost`/`focused` |

키 이벤트는 동작 실행의 보조 자료다. 이벤트가 기록되어도 화면 반응을 보지 못했다면 `pass`가 아니다.

## 증거와 파일 보존

실행기가 출력하는 증거 디렉터리에서 다음을 보존한다.

- `input-events.jsonl`: 관찰된 입력 이벤트, 시각, 눌림/해제, 연결 action, 포커스, 합성 의심 표식.
- `manual-review.json`: 입력별 결과, 표시/전투/편집기/원화 체크, 검사자 메모, 직접 관찰 플래그.
- 직접 촬영한 게임 화면, 편집기 재열기 및 게임 재적용 결과, 원화/프레임 팝 캡처: 임의의 검토 폴더에 원본 그대로 저장하고 해당 경로를 메모에 적는다.

이벤트 로그는 실제 장치 출처를 증명하지 않는다. 검수자는 물리 키보드와 마우스를 직접 조작하는 과정을 본 뒤 별도 JSON 필드로 이를 확인한다. 자동 입력/GUI 시험 증거를 사람 검수 기록으로 바꾸지 않는다. 무인 실행 상태는 항상 `BLOCKED_UNVERIFIED`, 종료 코드 `2`다.
