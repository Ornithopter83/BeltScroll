# Num5 회전 접촉 원화 검수 게이트

## 검수 범위와 보존 판정

검수 비교물은 [비교 보드](../../assets/art/review/player_skill2_spin_art_comparison.png)이며, 생성 스크립트는 [review_player_skill2_spin_art.gd](../../tools/review_player_skill2_spin_art.gd)다. v8 대기, Num4 safe 직선 돌진, 확보된 Num5 v1 접촉본, 그리고 v2 후보 칸을 같은 규칙으로 비교한다.

Num5 v1에 대한 기존 판정을 보존한다. 이 원화는 뻗은 주먹의 직선 타격처럼 보이며, 정지 접촉 그림만으로 회전 동작이 입증되지 않는다. 따라서 **Num5 v1은 회전 접촉 원화로 미수용**이다. 원화에서 눈에 보이는 요건을 확인할 수 없거나 캐릭터 identity가 다르면 해당 후보 역시 미수용이다.

검수 시점에 `assets/art/player/elven_fighter_skill2_spin_contact_v2_candidate_1254x1254.png`는 존재하지 않았다. v2는 비교 대상에 넣지 않았고 네 번째 칸에 **V2 FILE MISSING**으로 표시했다. v2 그림의 후방 회전 몸통, 수평 백피스트, 회전축 발, 팔 교차 여부는 아직 확인할 수 없다. 이 항목은 실제 v2 파일을 확보한 뒤 시각적으로 검수해야 한다.

## 동일 캔버스 및 미러 비교

- 각 원본의 전체 1254×1254 캔버스를 Lanczos로 192×192 게임 캔버스에 축소했다. alpha 경계에 맞춰 각 그림을 따로 확대하거나 위치를 재배치하지 않았다.
- 각 192×192 결과와 수평 반전본을 나란히 두고, 2배 nearest 확대하여 표시했다. 따라서 좌우 방향 차이 외에 캔버스 크기와 축척은 같다.
- 보드 크기는 1780×520이며 v2가 미확보인 동안 네 번째 칸을 비어 있는 대기 상태로 유지한다. v2 파일이 추가되면 해당 칸만 실제 원화와 미러본으로 채운다.

## 원본 파일 측정

alpha 여백은 alpha가 0보다 큰 픽셀을 기준으로 좌/상/우/하 순서로 측정했다. 고립 픽셀은 주변 8방향에 alpha가 0보다 큰 이웃이 없는 픽셀 수다. 원본 PNG를 수정하거나 safe 파생본을 만들지 않았다.

| 원화 | 파일 상태 | 캔버스 / 포맷 | alpha 경계 (x,y,w,h) | 여백 L/T/R/B | 고립 alpha 픽셀 |
|---|---|---|---|---|---:|
| v8 idle | 확보 | 1254×1254 / RGBA8 | 21,13,1195,1241 | 21 / 13 / 38 / 0 px | 543 |
| Num4 safe 직선 돌진 | 확보 | 1254×1254 / RGBA8 | 102,106,1050,1042 | 102 / 106 / 102 / 106 px | 0 |
| Num5 v1 접촉 | 확보 | 1254×1254 / RGBA8 | 0,27,1239,1227 | 0 / 27 / 15 / 0 px | 739 |
| Num5 v2 접촉 | 미확보 | — | — | — | — |

세 원본 파일은 모두 1254×1254라 원본 캔버스 크기 차이는 0×0 px다. 그러나 alpha 실루엣 크기는 다르다. 동일한 192×192 캔버스에서 alpha 5% 경계는 v8 idle 117×171px, Num4 safe 157×138px, Num5 v1 181×169px다. v2 크기는 파일을 받기 전에는 비교할 수 없다. idle과 v1은 적어도 한쪽 alpha 여백이 0px이고 고립 alpha 픽셀이 검출되므로 외곽 픽셀 품질 확인이 필요하다. 이 수치는 픽셀 기준 기계 측정이며 시각적 품질 승인으로 간주하지 않는다.

## 시각 판정 및 다음 검수 기준

보드에서 v8 idle, Num4 safe, Num5 v1의 얼굴·갈색 포니테일·청록색과 금색 의상은 같은 엘프 전사 identity로 보인다. identity 불일치가 눈에 띄지는 않았지만 최종 identity 승인은 사람 검수 항목이다. Num4 safe는 전방으로 뻗은 직선 주먹 포즈이고, Num5 v1도 팔을 수평으로 뻗은 주먹 타격으로 읽힌다. Num5 v1의 단일 접촉 그림은 몸통의 후방 회전, 백피스트, 회전축 발 또는 팔 교차를 분명히 입증하지 못한다.

v2를 확보하면 같은 보드에서 아래 항목을 직접 확인한다.

- [ ] v8 idle과 같은 얼굴, 귀, 포니테일, 청록색·금색 복장 identity다. identity가 불일치하면 미수용한다.
- [ ] 몸통이 타격 방향에 등을 보일 정도로 후방 회전한 실루엣이다.
- [ ] 주먹을 앞으로 곧게 찌르지 않고 수평 백피스트로 휘두른다. 직선 주먹이면 미수용한다.
- [ ] 회전축이 되는 발과 교차하는 팔이 192px 게임 크기에서도 구별된다.
- [ ] 1254×1254 RGBA8, alpha 여백, 고립 픽셀 수, 192px 실루엣 크기 차이를 표에 추가한다.
- [ ] 좌향·우향 미러 상태에서 포즈와 identity가 모두 읽힌다.

사람의 승인 전에는 원화를 본편, manifest 또는 allowlist에 등록하지 않는다. 비교 보드 생성은 원본 PNG를 변경하지 않는다.

## 재현

```powershell
godot --headless --path . --script res://tools/review_player_skill2_spin_art.gd
godot --headless --path . --script res://tests/player_skill2_spin_art_smoke.gd
```

비교 보드 생성기는 실행해 결과물을 만들었다. 이 문서의 수치와 검수 기록은 생성기 출력에 근거한다. smoke 스크립트는 작성했으나 별도 실행하지 않았다. Godot 실행 중 `user://logs` 쓰기와 Windows 인증서 저장소 읽기 오류가 출력되었지만, 생성기는 비교 PNG를 기록하고 정상 종료했다. 사람의 v2 포즈 승인과 본편 등록은 대기 중이다.
