# M6J 실제 전투 및 독립 편집기 수동 검수 게이트

## 목적과 인정 기준

이 절차는 실제 Godot 편집기에서 현재 씬을 F6로 실행한 플레이 확인과 독립 WinForms 편집기의 실제 버튼으로 저장값을 적용하는 과정을 순서대로 기록합니다. 자동화 검사는 이 수동 검수를 대신하지 않습니다. 실행기는 게임/편집기를 대신 실행하거나 키·마우스 입력을 보내거나 화면을 캡처하지 않습니다.

검수자는 각 항목을 직접 수행하고, 그 항목의 화면을 직접 캡처해 PNG 파일로 저장하고, 이미지를 직접 열어 눈으로 확인해야 합니다. 자동 입력, GUI 자동화, 자동 생성/수집 화면 캡처는 사람의 입력 또는 시각 승인 증거로 인정하지 않습니다. 사람의 실제 입력, 파일별 증거, 직접 시각 승인, 실행 파일 해시 중 하나라도 빠지면 전체 결과는 `BLOCKED_UNVERIFIED`입니다. 대화형 콘솔이 아닌 무인 실행도 항상 `BLOCKED_UNVERIFIED`입니다.

## 준비

1. Windows에서 저장소 프로젝트를 실제 Godot 4.7.2 편집기로 엽니다.
2. `scenes/review/m6i_combat_test_arena.tscn`을 열어 활성 씬으로 둡니다. 이 검수는 Godot 편집기에서 **F6 (현재 씬 실행)** 으로 시작합니다. 게임을 임의의 별도 실행 명령으로 대체하지 않습니다.
3. 독립 WinForms 편집기 `BeltScrollEditor.exe`와 저장/적용할 프로젝트의 `data/editor/overrides.json` 경로를 준비합니다.
4. 검수별 PNG를 담을 폴더를 만들고 사람이 직접 화면을 캡처할 도구를 준비합니다. 자동 캡처는 사용하지 않습니다. 각 항목에는 서로 다른 PNG 파일을 지정합니다.
5. PowerShell 5.1에서 UTF-8 출력 인코딩을 설정합니다.

```powershell
$utf8 = New-Object System.Text.UTF8Encoding($false)
[Console]::OutputEncoding = $utf8
$OutputEncoding = $utf8
Get-Content -Encoding UTF8 .\docs\review\m6j_manual_combat_editor_gate.md
```

## 순서대로 검수 및 기록

아래 실행기는 입력을 보내거나 앱을 실행하지 않습니다. 콘솔이 열려 있고 Godot F6 실행 장면을 띄운 상태에서 실행합니다. 각 프롬프트를 읽고 실제 조작/관찰을 마친 다음 답합니다.

```powershell
.\tools\run_m6j_manual_combat_editor_review.ps1
```

1. 검수자 이름, Godot `godot*.exe`, 독립 `BeltScrollEditor.exe`, 저장될 `data/editor/overrides.json`의 경로를 입력합니다. 실행기는 현재 Git HEAD, 두 EXE, override JSON의 SHA-256을 기록합니다.
2. Godot 창 제목을 입력한 뒤 각 항목에서 직접 키보드를 조작하고 결과를 확인합니다. 키 입력은 물리 키보드에서 발생해야 합니다.

   - **물리 J 연타 3콤보:** J를 빠르게 세 번 눌러 1→2→3타 단계와 콤보 종료/초기화를 확인합니다.
   - **Num4:** 숫자열 4가 아닌 키패드 Num4로 돌진 phase와 쿨다운 변화를 확인합니다.
   - **Num5:** 키패드 Num5로 회전 공격 phase와 쿨다운 변화를 확인합니다.
   - **적 반격:** Raider의 공격이 실제로 플레이어에게 명중하고 HP가 변하는지 확인합니다.
   - **경직:** 피격에 따른 넉백/경직 잔여 시간 및 경직 중 입력 제한을 확인합니다.
   - **복귀:** 경직이 끝난 뒤 이동이나 공격 입력이 다시 처리되는지 확인합니다.
   - **R 재시작:** R을 눌러 씬, 플레이어/적, HP가 초기화되는지 확인합니다.

3. 각 항목마다 그 장면이 보이게 사람이 직접 화면을 캡처해 별도 PNG로 저장합니다. PNG를 직접 열어 화면을 확인하고, 실행기가 묻는 판정에 `PASS`/`FAIL`, 실제 입력 출처에 `physical-keyboard`, 증거 이미지 시각 승인에는 `I_VISUALLY_APPROVE`를 입력합니다. 화면을 확인하지 않았거나 증거를 만들지 못했다면 YES/PASS라고 답하지 말고, 증거 경로를 비우거나 항목 관찰에 `NO`로 답합니다.
4. Godot 항목이 끝난 뒤 독립 WinForms 편집기를 실제로 엽니다. 창 제목, 수정할 필드명, 수정 전/후 값을 입력합니다. 편집기에서 값을 직접 바꾸어 저장하고 저장 상태를 확인합니다. HUD에 표시되거나 적 HP 등 화면상 결과로 적용 여부를 알아볼 수 있는 런타임 필드를 선택합니다. 저장된 JSON 파일의 SHA-256은 저장 단계 뒤 다시 기록됩니다.
5. 실제 편집기의 **전투 연습장 실행** 버튼을 마우스로 클릭하고 별도 Godot 프로세스가 열리는지 확인합니다. 스크립트가 Godot를 실행한 것으로 간주하지 않습니다.
6. 별도 연습장 화면에서 편집한 필드가 저장한 값으로 적용됐는지 직접 확인합니다. 이 항목은 화면 관찰 결과와 저장된 override SHA-256에 연결됩니다.
7. 저장, 버튼 클릭, 값 적용 각각의 장면도 별도 PNG로 직접 캡처하고 열어서 확인한 뒤 판정합니다.

모든 항목은 동일한 검수자가 직접 수행하는 것이 권장됩니다. 각각의 기록에는 실행 파일 경로, 적용 가능한 실행 파일 SHA-256, 입력 출처, 관찰 시각, 검수자, 판정, 증거 경로와 SHA-256이 포함됩니다. 세션 공통 메타데이터에는 현재 Git commit SHA와 저장 JSON의 저장 전/저장 후 SHA가 포함됩니다. 실행기는 증거 파일의 PNG 시그니처와 SHA-256을 확인하지만 화면의 진위나 실제 사람 조작 여부를 자동 판별한다고 주장하지 않습니다. 경로가 없거나 PNG 형식이 아닌 증거는 해당 항목을 통과시킬 수 없습니다. 동일 파일 또는 중복 바이트 증거 재사용도 허용되지 않습니다.

## 보고서와 종료 상태

기본 보고서는 `.qa_logs/m6j_manual_combat_editor_review.json`에 UTF-8로 작성됩니다. `-ReportPath`로 다른 보고서 경로를 지정할 수 있습니다.

| 상태 | 의미 | 종료 코드 |
|---|---|---:|
| `PASS_HUMAN_REVIEW` | 필수 10개 항목을 모두 실제 조작/관찰했고, 고유 PNG와 직접 시각 승인, SHA 정보가 유효함 | 0 |
| `FAIL` | 검수자가 직접 본 항목 중 하나 이상을 `FAIL`로 판정했으며 필수 증거는 갖춤 | 1 |
| `BLOCKED_UNVERIFIED` | 무인/리디렉션 실행, 누락된 PNG/시각 승인, 잘못된 입력 출처, 실행 파일/저장 JSON/commit SHA 누락 등으로 검증되지 않음 | 2 |

실행 전부터 표준 입력/출력이 리디렉션된 경우에도 보고서 생성 시도 후 `BLOCKED_UNVERIFIED`를 반환합니다. 보고서의 `policy.automatedInputAccepted`, `policy.automatedCaptureAccepted`, `policy.unattendedExecutionCanPass`는 모두 `false`여야 합니다. 보고서의 파일 해시와 사용자 입력은 검수 기록이며, 자동으로 진짜 사람 입력/화면임을 증명하는 기술 검증으로 해석하지 마세요. 최종 사람 승인은 본인이 실제 절차를 따랐다는 책임 있는 확인입니다.
