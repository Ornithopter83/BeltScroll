# M6L PlayerArt ↔ PoseBlender 연속 Window 인계 검수

## 범위

`tests/m6l_pose_handoff_window_smoke.gd`는 Godot GUI 렌더러의 실제 Window에서 Player 씬을 띄운 뒤, 렌더 완료 신호마다 `M6L_FRAME` 한 줄을 출력한다. 걷기 진입, 1·2·3타의 startup/contact/recovery, 콤보 사이 전환, 공격 종료 후 걷기, 방향 반전, 공격 취소, 피격·경직 및 걷기 복귀를 이어서 표본화한다. 이번 실행은 연속 Window 프레임 62개를 기록했다.

각 행에는 실제 프레임 간격, 애니메이션 상태와 PoseBlender 키, PlayerArt와 PoseBlender 계층 알파, 블렌더 내부 두 스프라이트의 알파와 외부 계층 알파를 곱한 유효 알파, PlayerArt의 알파 발점과 현재 표시 원화의 발점, 회전, 크기, 임시 상태 프레임 키를 담는다. 공격 원화의 발점은 M6K에서 등록한 텍스처별 지지점으로 측정하며, 내부 두 원화가 교차되는 동안 각 텍스처의 지지점을 따로 적용한다. 완료된 외부 알파 전환은 첫 변화 표본부터 완료 표본까지 재서 요약에 남긴다.

## 수정과 측정 결과

- PlayerArt ↔ PoseBlender 전환 길이 `0.105s`와 공격 hitbox 활성 시간 `[0.105, 0.12, 0.14]`를 유지했다. KO → 피격 → 스킬 → 공격 우선순위도 그대로다.
- cubic easing은 실제 Window에서 프레임 간격이 약 38–50ms일 때 알파 변화가 한 프레임에 집중됐다. 외부 계층 크로스페이드를 경과 시간에 비례하는 선형 진행으로 바꿨다. 최신 재실행에서 완결 전환 7회의 시작·완료 표본 간격은 `111.11–116.67ms`였다. 이 값에는 실제 프레임의 표본 양자화가 포함되며, 런타임 상수는 계속 105ms다.
- 공격 포즈의 지지발 좌표를 PlayerArt 알파 발점에 정렬했다. 공격 지지점과 PlayerArt 발점의 최대 오차는 `0.00006px`였다.
- 최대 인접 프레임 알파 변화는 `0.40476`, 두 표시 레이어의 합성 유효 알파 합 최대 오차는 `0.00005`였다. 회전 최대 프레임 변화는 `0.17498rad`, 크기 변화는 `0.04449`였다. 테스트에서 0.60을 넘는 단일 프레임 불투명도 절단, 0.30rad를 넘는 회전 점프, 0.18을 넘는 크기 점프는 나타나지 않았다.
- 최신 Window 스모크 결과: `fail=0`, 실제 `frame_post_draw` 기록 `69`프레임, 완결 handoff `7`, 발점 오차 최대 `0.00006px`.

## 실행

Windows PowerShell에서:

```powershell
$OutputEncoding = [Console]::OutputEncoding = New-Object System.Text.UTF8Encoding($false)
& 'C:\Project\Godot\godot.exe' --path . --script 'res://tests/m6l_pose_handoff_window_smoke.gd'
```

`M6L_FRAME`은 프레임 단위 원시 기록이고 `M6L_SUMMARY`는 누적 측정치다. 테스트 러너는 공격·피격 단계를 직접 설정해 렌더 연속성을 통제하므로 키 입력 시점이나 충돌 판정을 검증하지는 않는다. hitbox 활성 시간은 기존 컨트롤러의 상수와 비교했고, gameplay 코드는 수정하지 않았다.

## 시각 승인과 원화 경계

알파 합 검사는 겹친 두 레이어가 불투명도를 이중으로 더하지 않는지 수치로 확인한다. 이 검사는 서로 다른 실루엣이 105ms 동안 겹쳐 보일 때의 미관상 잔상 여부에 대한 사람의 시각 판정을 대신하지 않는다. 따라서 Window 자동 검수 결과만으로 시각 승인을 내리지 않으며, 별도 화면 검토는 대기 상태다.

현재 보행 표현은 정지 전신 그림에 임시 변형을 적용한다. 실제 다리 관절 보행, 좌우 발 디딤 원화 또는 승인된 신규 애니메이션으로 간주하지 않는다. 검수 표식은 `visual_signoff=pending`이다.

최신 재실행 명령은 위 Godot Window 실행 명령과 같다. 실행은 통과했지만 F6에서의 수동 입력·시각 확인은 하지 않았다. 두 실루엣이 겹칠 때의 미관상 잔상 승인은 계속 보류다.
