# M6L 보행 보폭 연속 검토 게이트

## 실행과 조작

Godot 에디터에서 `scenes/review/m6k_walk_cycle_preview.tscn`을 열고 **F6**으로 실행한다. 검토 창은 assets/art/player에서 확인된 기존 `run_stride` v1~v5 원화와 `walk_opposite_stride`를 포함한 추가 walk/run stride PNG를 읽는다. `_safe`가 포함된 안전 매트 파생 원화는 새 보폭 원화가 아니므로 재생 목록에서 제외한다. 파일명에 `resource`가 들어가는지를 도착 기준으로 사용하지 않는다. 현재 `elven_fighter_walk_opposite_stride_v1_candidate_1254x1254.png`가 있으므로 독립 후보 프레임으로 표시된다. `elven_fighter_walk_passing_v1_candidate_1254x1254.png`도 존재해 독립 검토 프레임으로 표시되며, 이름에 passing이 있어도 승인이나 통과 판정을 뜻하지 않는다. 해당 파일이 없으면 passing 프레임을 만들지 않는다.

각 후보 원화의 투명 영역을 제외한 알파 실루엣을 실제 표시 높이 **192px**에 맞춰 공통 바닥선 위에서 순차 재생한다. 기본은 재생 중이며 **Space**로 재생/일시정지, **← / →**로 정지 상태에서 이전/다음 원화를 한 프레임씩 진행한다. 새 추가 후보는 파일이 실제 검색되고 읽힐 때만 별도 프레임으로 등장한다. RESOURCE 미도착 더미 프레임은 만들지 않는다.

현재 시각 검토 결과 기존 `run_stride` v1~v5는 모두 같은 전진 보폭 phase로 분류되어 각 프레임과 하단 요약에 **FAIL**이 표시된다. 세부 원화가 달라도 좌우 접지 교대에 필요한 반대 phase가 아니기 때문이다. 새 `walk_opposite_stride` 원화는 확보되어 독립 프레임으로 보이지만, 선 자세 한 장만으로 반대 접지와 팔 반대 흔들림을 확인할 수 없어 통과 후보로 판정하지 않는다. `walk_passing`도 별도 프레임으로 비교하되 같은 단일 프레임 제한으로 지지발 고정과 사이클 내 passing 타이밍을 판정할 짝이 없어 미승인 상태를 유지한다. 상대 phase 원화가 추가될 때만 교대 여부를 다시 검토한다.

이 프레임 순서는 확보된 원화를 빠르게 검토하기 위한 프리뷰다. 서로 다른 버전의 그림을 한 제작용 보행 애니메이션으로 인정하거나, 원화 한 장에서 얻을 수 없는 접지 이동을 만들어내지 않는다. 접지 지점은 별도 수동 마커로 위장하지 않으며, 하단 알파 중심 값은 참고값으로만 표시한다.

## 관찰 및 판정

- 좌우 발이 교대로 접지하는가? 접지에서 반대 발이 명확히 들리는가?
- 접지하는 지지발이 프레임 전환 때 고정된 것처럼 이어지는가, 미끄러지거나 튀는가?
- 팔은 다리와 반대 위상으로 흔들리는가?
- 골반 높이가 프레임 사이에서 튀지 않는가?
- 공통 바닥선에서 좌우 위치가 불필요하게 이동하거나 화면상 흔들리는가?
- 실제 192px 표시에서도 발, 팔, 몸통의 동작 차이가 읽히는가?
- 동일 보폭 원화를 반복한 가짜 교대가 없는가?

같은 원화의 SHA-256 픽셀 데이터가 중복되면 화면에 **FAIL · 동일 원화 중복**을 표시한다. 현재 run v1~v5는 검토에서 같은 전진 phase로 분류되어 그룹 FAIL도 표시한다. 시각적으로 같은 보폭인 서로 다른 파일은 같은 phase 실패로 처리하고, 두 프레임을 교대로 써서 보행 주기처럼 보이게 해서는 안 된다. phase 분류는 현재 원화에 대한 검토 메모이며 새 이미지의 중복 자동분석은 아니다. 다른 항목은 시각 검토이며 자동 승인이 아니다.

## 미승인 격리

각 프레임과 미리보기는 **미승인**으로 표시한다. 이 씬은 후보 원화를 읽고 검토할 뿐이며 본편 manifest, reviewed allowlist, Player 씬에 등록하거나 수정하지 않는다. 독립 검토 프레임에 포함된 사실은 승인 또는 본편 사용 허가를 뜻하지 않는다. 결과는 사람의 검토 대기 상태다.

## 2026-10-10 실행 기록

`tests/m6l_walk_cycle_preview_smoke.gd`는 Godot 4.7.2에서 통과했다. 후보 원화 처리는 `748.9ms`였고, 192px 표시 높이, 연속 cadence, Space 일시정지·재생, 좌우 한 프레임 이동, 후보 존재 시에만 passing 추가, 동일 원화 및 같은 전진 보폭 phase의 **FAIL**, 격리 조건을 검사했다. 실제 렌더 캡처는 `.godot/m6l_high_review_captures/frame_00.png`–`frame_06.png`에 남아 있으며 반대 보폭과 passing은 각각 6/7, 7/7로 분리 표시된다.

이 실행은 테스트 러너와 Window 캡처다. 에디터에서 F6로 조작해 사람이 교대 접지·발 들기·반대 팔·지지발 고정·골반 높이·좌우 이동을 승인한 것은 아니다. 따라서 두 후보 상태는 미승인이고 보행 완성 판정은 보류다.
