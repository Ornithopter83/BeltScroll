# 1타 startup safe 후보 검수 게이트

## 상태

기존 startup 후보를 원본 보존 상태로 검사하고 별도 safe 후보로 정규화했습니다. 기계 검사와 비교판은 준비됐지만 사람의 시각 승인 전입니다. 후보는 애니메이션, Player 씬 또는 런타임 리소스에 연결하지 않았습니다.

## 원본 보존과 정규화

- 입력 `assets/art/player/elven_fighter_attack1_startup_v1_candidate_1254x1254.png`와 출력 `assets/art/player/elven_fighter_attack1_startup_v1_safe_candidate_1254x1254.png` 모두 1254×1254 RGBA8 PNG입니다.
- 원본 SHA-256: `d417044999608925e5e2f0b9e1a3a0c696434b3600fc1c74fdf795b9fa056a56`.
- 원본 alpha 경계는 (0, 3)에서 1230×1233px입니다. 8방향 이웃이 없는 원본 alpha 픽셀 201개를 먼저 제거해 재배치 기준 상자를 (0, 8)에서 1230×1221px로 잡았습니다.
- 전체 실루엣에 균일 비율 **0.873171**을 적용해 1074×1066px로 축소하고 (90, 94)에 놓았습니다. crop은 고립 픽셀 정리 후의 alpha bounds만 사용했으며 실루엣을 잘라 맞추지 않았습니다. Lanczos 리샘플링은 premultiplied alpha로 수행했습니다.
- 리샘플링에서 새로 생긴 고립 alpha 픽셀 44개를 제거했습니다. 출력의 고립 alpha 픽셀은 0개이고, alpha 0 바탕의 RGB는 0입니다. 윤곽 부근의 강한 적색 오염 207픽셀은 주변 전경색으로 복원했습니다. 원래 alpha 모양은 색 정리 과정에서 보존합니다.
- 최종 nonzero-alpha 경계는 (90, 94)에서 1074×1066px이며 여백 L/T/R/B는 **90/94/90/94px**입니다. 네 가장자리의 모든 픽셀은 완전 투명합니다.

## 3배 비교와 기준점

`assets/art/review/player_attack1_startup_safe_comparison.png`는 2256×760px입니다. 세 원화를 같은 1254px 캔버스에서 576×576px로 표시해 192px 게임 스프라이트의 3배 크기로 비교합니다. 노란 십자는 각 원화에서 alpha 5% 이상인 가장 낮은 행의 연속 구간 중심입니다.

| 포즈 | alpha bounds (px) | 최하단 기준점 (원본 캔버스 좌표) |
|---|---:|---:|
| v8 대기 | (333, 148), 652×965 | (951, 1112) |
| 1타 startup safe | (284, 242), 754×836 | (326, 1077) |
| 승인된 1타 접촉 contour | (164, 128), 995×995 | (1073, 1122) |

safe 정규화에 따른 startup 기준점은 원본의 **(270, 1134)**에서 **(326, 1077)**로 이동했습니다. 이동량은 **(+56, −57)px**이며 192px 게임 표시 높이 환산 시 약 **(+10.1, −10.2)px**입니다. 이 최하단 점은 포즈마다 다른 발에서 잡힐 수 있습니다. v8과 접촉은 화면 오른쪽 장화, startup은 화면 왼쪽 장화 쪽의 최하단 alpha 행이므로 위 좌표 차이는 공통 지지발 tracking 값이 아닙니다.

정지 그림에서 보이는 주먹 이동은 이렇습니다. v8은 양 주먹을 몸 앞 가드에 두고, startup은 화면 왼쪽 주먹을 왼쪽·뒤쪽으로 당기는 동시에 화면 오른쪽 주먹을 얼굴 가까이 둡니다. 승인 접촉은 오른쪽 주먹과 팔을 어깨 높이로 수평 전진시키고 왼손은 몸 가까운 가드에 남깁니다. 따라서 접촉까지의 주요 동선은 startup의 오른쪽 얼굴 가드에서 오른쪽 전방으로의 뻗기입니다. 세 정지 포즈만으로 프레임 사이 궤적, 타격 순간, 속도 또는 실제 지지발을 확정할 수 없습니다.

얼굴과 귀는 세 패널 모두 화면 오른쪽을 향하는 측면 얼굴과 뾰족한 가까운 귀가 보이며, 포니테일·금색 머리 장식·청록색 상의·갈색 장갑의 identity가 이어집니다. startup은 포즈가 더 작고 몸통이 접혀 얼굴과 귀가 상대적으로 가드 주먹에 가까워 보입니다. 접촉은 팔이 뻗으며 얼굴 옆 공간이 열립니다. 이 항목은 픽셀 존재 확인을 통과했을 뿐, 세부 드로잉·윤곽·오염 제거의 품질은 사람의 3배 확대 시각 확인이 남아 있습니다.

## 검수 결과와 승인 대기

| 기계 검사 | 결과 |
|---|---|
| 1254×1254 RGBA8 출력 | 통과 |
| 각 방향 nonzero-alpha 여백 90px 이상 | 통과: 90/94/90/94px |
| 외곽 완전 투명 및 완전 투명 픽셀 RGB 0 | 통과 |
| 고립 alpha 제거 | 통과: 출력 0개 |
| 균일 축소 | 통과: source의 고립 픽셀 제외 경계와 출력 bounds 비율 일치 |
| 포화 적색 edge spill | 통과: 원본 대비 감소; 국소 207픽셀 정리 |
| 얼굴·귀·양 장갑·양 장화 alpha 영역 | 통과: 각 영역에 유효 alpha 유지 |
| 원본 보존 | 통과: 준비 스크립트 종료 시 원본 SHA-256/바이트 불변 확인 |
| 사람의 시각 승인과 본편 연결 | 대기; 승인 전 연결 금지 |

Smoke 로그에는 사용자 작업 폴더 `user://logs` 및 시스템 CA 인증서 접근 실패가 출력됐지만, 준비 스크립트와 smoke는 종료 코드 0으로 끝났고 모든 대상 검사 항목은 통과했습니다. 이는 Godot 로그/인증서 환경 메시지이며 소스·아트 검사 실패가 아닙니다.

## 재현

```powershell
godot --headless --path . --script res://tools/prepare_player_attack1_startup_safe.gd
godot --headless --path . --script res://tests/player_attack1_startup_safe_smoke.gd
```

Smoke 통과는 사람의 시각 승인을 대체하지 않습니다. 검수자는 비교판에서 얼굴·귀·주먹/팔 동선·장갑·양발·윤곽 색 번짐을 확인하고, 별도 승인 뒤에만 게임 연결을 진행해야 합니다.
