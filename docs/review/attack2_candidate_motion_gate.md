# 2타 후보 연속 모션 검수 게이트

## 격리 캡처

[후보 모션 캡처](../../assets/art/review/player_attack2_candidate_motion_strip.png)는 실제 Godot Window와 Viewport를 1920×1080으로 확인한 뒤 격리 장면에서 만들었습니다. 1타 접촉 → 2타 safe 중간 → v6 safe 접촉 → 기존 3타 접촉 순서로 각각 우향과 좌향을 재생했습니다. 좌향은 원화별 `flip_h` 한 번만 적용했습니다. 캡처 행은 우향 지지발 고정, 우향 alpha 스텝, 좌향 지지발 고정, 좌향 alpha 스텝입니다. 본편 Player나 기본 애니메이션 런타임에는 연결하지 않았습니다.

각 포즈는 1254px 원본 캔버스를 같은 배율로 표시했습니다. 노란 표식은 alpha 5% 기준 최하단 행의 좌우 끝 중앙이며, 민트 표식은 원화에서 따로 고른 지지발 후보입니다. 민트 좌표 `[1073, 1064, 1100, 1000]`은 원본 캔버스 x값입니다. 3타 후보는 오른쪽 부츠를 지지발 후보로 잡았습니다. 자동 alpha 측정값을 실제 접지 판정으로 취급하지 않도록 두 표식을 분리했습니다.

## 실제 Window 노출 프레임 수

도구는 각 구간에서 `process_frame` 뒤 `RenderingServer.frame_post_draw` 완료 횟수를 세고, 중간 시점과 구간 종료 시각을 기록합니다. 이는 Window Viewport가 완료한 렌더 프레임 수입니다. 모니터 패널의 물리적 광자 노출을 측정한 값은 아닙니다.

| 포즈 | 기준 시간 | 실제 Window 구간 시간 | 완료 렌더 프레임 | 메모 |
|---|---:|---:|---:|---|
| 1타 접촉 | 105ms | 127.1–127.8ms | 4 | 중간 시점 2회 렌더 |
| 2타 safe 중간 | 50ms | 63.7–66.7ms | **2** | **중간 시점 1회, 구간 전체 2회 렌더** |
| v6 safe 접촉 | 120ms | 126.8–128.4ms | 4 | 중간 시점 2회 렌더 |
| 기존 3타 접촉 | 140ms | 158.2–159.9ms | 5 | 중간 시점 3회 렌더 |

각 값은 두 방향 × 두 정렬 방식으로 반복한 네 회 측정의 범위입니다. 목표 50ms 중간은 이 Windows 창/렌더 조건에서 약 64–66ms 유지되어 2회 완성 프레임으로 보입니다. 따라서 한 프레임짜리 섬광은 아니지만 짧고, 1타에서 중간으로 바뀌는 포즈 차가 남아 있어 빠른 재생에서 프레임 팝으로 느껴지는지 최종 시각 판정이 필요합니다. 프레임 단위 대기 때문에 요청 시간보다 실측 시간이 길어지는 현상도 수치로 남겼습니다.

## 217px 변화의 원인과 두 정렬 방식

실제 원화의 alpha 5% 최하단 행 중앙은 v6 접촉 `(1100, 1143)`, 3타 `(274, 1145)`입니다. x 차이 826 원화 px에 330px 표시 높이 기준 배율 `330/1254`를 적용하면 `217.4` 화면 px입니다. 이 급변은 낮은 alpha가 잡힌 부츠가 오른쪽에서 왼쪽으로 바뀌면서 생깁니다. 두 y 좌표는 거의 같고 x 좌표만 크게 달라지므로 캔버스 높이, 표시 배율, 전신 크기 변화가 원인이 아닙니다. 이 값은 하단 alpha 접점의 변화이며 지지발이 217px 이동했다는 증거가 아닙니다.

| 정렬 | 고정 기준 | 캡처에서 비교할 점 |
|---|---|---|
| 지지발 고정 | 포즈별 민트 지지발 후보를 패널 바닥 기준점에 고정 | v6와 3타에서 다른 부츠를 지지발 후보로 삼아도 몸체 이동을 줄입니다. 후보 선택이 맞는지 시각 확인이 필요합니다. |
| 원화 pivot 고정·의도적 스텝 | 원본 캔버스 중앙 x를 고정하고 최하단 접점이 움직이도록 둠 | v6→3타에서 노란 기준점이 부츠를 바꾸며 원화 기준 217.4px(330px 높이 환산) 이동합니다. 이 이동을 의도한 스텝으로 쓸지 정해야 합니다. |

캡처판은 4행 비교에 맞춰 인물을 176px 캔버스 높이로 축소했으므로 그 이미지 안의 노란 기준점 이동은 약 116px입니다. `217.4px` 수치는 이전 검수와 같은 330px 표시 높이로 정규화한 비교 수치입니다. 스텝 행은 root pivot(원본 캔버스 중앙 x)을 고정해 이 접점 변화를 패널 안에서 직접 보이고, 발 고정 행은 선택한 지지발 후보를 기준점에 고정합니다. 화면에서 읽기 쉽도록 캡처는 원본 전체 캔버스를 사용하며 알파 영역을 잘라내지 않습니다.

## 결함 관찰 기록

- **잘림:** 네 원화 모두 원본 1254×1254 캔버스의 alpha 경계가 캔버스 안에 있고, 격리판에서 전체 원본을 표시했습니다. 캡처에서 인물 실루엣 잘림은 보이지 않습니다.
- **미러 중복:** 패널마다 스프라이트 하나만 생성하고 좌향에서만 `flip_h=true`를 적용합니다. 좌우 포즈가 겹쳐 보이는 중복 렌더는 없습니다.
- **프레임 팝:** 보간 없이 네 정지 포즈를 순서대로 전환합니다. 50ms 중간은 실제 두 렌더 프레임이며, 1타에서 뒤돌림 중간으로의 변화와 v6에서 위쪽 주먹 3타로의 변화가 즉시 일어납니다. 모션 팝 여부는 담당자의 시각 승인 항목입니다.
- **발 미끄러짐:** 초록 지지발 후보를 고정하는 행은 3타에서 최하단 alpha 중심과 지지발 후보가 다른 위치임을 보입니다. 원화 pivot 고정 행은 세 번째 접촉에서 최하단 alpha 부츠가 바뀌며 약 217px(330px 표준 표시 기준) 이동합니다. 본편 접지 방식으로 채택하기 전에 어느 부츠가 체중을 받는지 확인해야 합니다.

## 재현과 승인 상태

```powershell
godot.exe --path . --script res://tools/capture_attack2_candidate_motion_review.gd
godot.exe --headless --path . --script res://tests/attack2_candidate_motion_review_smoke.gd
```

스모크 검사는 캡처 크기, 두 표식, 원화 입력, 50ms 입력 길이, 217px 환산 및 기본 manifest의 기존 승인 상태를 확인하도록 작성했습니다. 이 작업에서는 캡처 도구를 실행해 PNG를 생성했고, 별도의 smoke 실행은 하지 않았습니다.

기본 `data/art/animation_manifest.json`의 승인 상태는 변경하지 않았습니다. 2타 중간과 v6 safe 접촉은 검수 후보로 유지되며, 본편 원화 또는 본편 모션의 승인을 의미하지 않습니다. 잘림, 미러 중복은 캡처 관찰상 발견되지 않았습니다. 프레임 팝의 수용 여부와 지지발 후보/의도적 스텝 중 채택할 정렬은 시각 검토 후 결정해야 합니다.
