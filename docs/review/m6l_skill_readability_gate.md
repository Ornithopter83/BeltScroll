# M6L Num4·Num5 기술 가독성 검수 게이트

## 실행

Godot 에디터에서 `scenes/review/m6l_skill_readability_lab.tscn`을 열고 **F6**으로 실행한다. 프로젝트의 실제 Player 장면과 실제 `Skill1Hitbox` / `Skill2Hitbox`를 사용한다. 실험장은 두 Player의 키보드 입력 폴링만 멈추고, 실제 스킬 상태 머신·이동·애니메이터·효과를 각기 다른 레인에서 구동한다.

| 키 | 동작 |
| --- | --- |
| `4` 또는 키패드 `4` | 왼쪽 Player에서 Num4 직선 돌진 재생 |
| `5` 또는 키패드 `5` | 오른쪽 Player에서 Num5 제자리 회전 재생 |
| `Space` | Num4와 Num5 동시 재생 |
| `R` | Player, 대상, 쿨다운과 중단 상태 초기화 |
| `X` | 기술 취소. 양쪽 효과 및 판정이 꺼지는지 확인 |
| `H` | 양쪽 Player 피격. 기술 중단 뒤 효과 소거 확인 |
| `K` | 양쪽 Player KO. 쓰러진 뒤 효과 소거 확인 |

## 비교 관찰

두 레인을 같은 화면에서 보며 준비·활성·회복을 각각 관찰한다. 상태 문구는 실제 Player 상태와 스킬별 Area2D의 `monitoring`을 표시한다. 가는 선은 공격 궤적 참고선, 금색 십자와 발 표식은 원점·축·지지 위치이며, 색이 선명해지는 실제 모양 외곽선은 Player 장면의 CollisionShape2D 크기와 변환을 읽어 그린 히트박스다. Num4는 108×58 직사각형, Num5는 반경 64 원형이다.

화면 하단 후보 그림은 각 기술의 기존 미승인 원화를 축소해 분리 표시한다. 후보 그림은 참고만 하며 Player의 텍스처, 애니메이션 또는 승인 상태를 변경하지 않는다.

## 판정 기준

이 비교장은 자동 PASS를 내지 않는다. 다음 항목을 모두 직접 확인하고 기록하기 전까지 판정은 **보류**로 둔다.

- 실루엣과 몸통 동작만 보아도 Num4의 직선 전진·주먹 돌진과 Num5의 제자리 상체 회전·백핸드 궤적을 구분할 수 있다. 색 또는 이펙트를 가렸을 때 구분되지 않으면 **FAIL**이며 PASS할 수 없다.
- Num4는 발과 몸이 공격 방향으로 실제 전진하며 주먹 궤적이 일직선이고 실제 사각 히트박스 및 대상 접촉 위치와 맞는다.
- Num5는 지지발과 회전축이 제자리에 남고 어깨·몸통·주먹이 회전한다. 주먹 원호와 실제 원형 히트박스 위치가 맞는다.
- 준비 예고, 활성 판정, 회복 감속이 상태 전이 순서와 효과 잔류까지 일치한다.
- `X`, `H`, `K` 각각 실행 직후 기술 효과와 히트박스가 사라지며 KO 실루엣에도 스킬 잔상이 남지 않는다.
- 하단 원화 후보는 플레이 장면과 분리된 참고 이미지로만 표시된다.

## 2026-10-10 실제 Player Window 스모크

`tests/m6l_skill_readability_window_smoke.gd`를 Godot 4.7.2의 실제 Window에서 실행해 통과했다. 두 production Player가 준비→활성→회복을 완료했고, Num4는 실제로 전진해 직사각형 판정으로 대상을 맞혔으며 Num5는 `8px` 이내로 지지 위치를 유지하며 원형 판정으로 대상을 맞혔다. Num5 최대 회전은 `0.55752rad`, 최대 표본 간 회전 변화는 `0.15846rad`였다. 취소·피격·KO에서 양 기술의 효과가 사라졌고 실제 hitbox/회복 종료도 확인했다.

이 수치는 상태 머신과 이동·회전 동작의 자동 검증이다. F6 수동 관찰은 하지 않았고, 색·효과를 가렸을 때 몸 실루엣과 주먹 동작만으로 기술을 구별하는 사람의 판정은 아직 없다. 후보 원화는 참고 패널에만 남으며 최종 판정은 계속 **보류**다.
